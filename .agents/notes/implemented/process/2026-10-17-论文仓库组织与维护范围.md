# Agent Note: 论文仓库组织与维护范围

Status: implemented

## 问题

仓库用于精选不同研究主题的优质论文。输入压缩包的顶层目录均为 `translate_zh_CN`，直接解压到同一位置会造成文件名冲突。仓库需要稳定的阅读入口和文档维护规则。

## 决策

以 arXiv ID 分目录存放论文，移除压缩包中的通用顶层目录，保留目录内部的文件名、相对路径和内容。README 维护论文入口及关注点。

从 agent-maintenance 固定提交采用三个维护技能及其引用资源，按论文仓库调整根指令和 Notes 入口。当前工作不需要运行应用或构建软件，因此采用 Git、EditorConfig 与忽略规则，后续有实际检查需求时再引入相应工具链。

## 考虑过的替代方案

直接在仓库根解压多个压缩包会使同名源码与图片混在一起。保留每个压缩包的通用顶层目录又会增加阅读层级。按 ID 分目录并去掉通用顶层目录，能保留论文内部引用并缩短入口路径。

完整复制维护包的开发依赖、脚本、hooks 与 CI 会增加安装和维护工作；当前只需管理论文材料与少量自有文档，因此按实际范围采用规则资源。

## 后果

新增论文须同步 README；第三方论文材料不参与批量格式化。维护资源保留来源提交和许可，后续更新需核对项目适配内容。

按 arXiv ID 排序，六个论文目录分别有 22、48、38、6、24、38 个文件。删除对应压缩包前，已按相对路径逐文件比较归档内容与落盘文件的 SHA-256，176 个文件全部一致。论文入口和维护文档的本地链接已核验；未运行 LaTeX 编译，也未验证外部网页。
